<h1>schemasafe</h1><p>A free, offline command-line scanner that reads a PostgreSQL migration <code>.sql</code> file and flags risky statements before you run them. It runs locally and sends no data anywhere.</p><h2>Usage</h2><pre>python -m schemasafe migration.sql</pre><p>Prints one line per finding, for example <code>line 1 [HIGH] DROP_TABLE: Drops a table and all of its data.</code> The exit code is 1 if anything is flagged, 0 if clean, and 2 if no file is given, so it works in CI.</p><h2>Rules</h2><ul><li><b>High:</b> DROP TABLE, DROP COLUMN, TRUNCATE, DELETE without WHERE</li><li><b>Medium:</b> UPDATE without WHERE, SET NOT NULL, ADD COLUMN NOT NULL without DEFAULT, ALTER COLUMN TYPE</li><li><b>Low:</b> CREATE INDEX without CONCURRENTLY, RENAME</li></ul><h2>How it works</h2><p>The scanner blanks out comments, string literals and dollar-quoted blocks (keeping line numbers), splits the file into statements on semicolons, and applies one regex per rule to each statement.</p><h2>Running the tests</h2><p>No install needed. From the repo folder run:</p><pre>python -c "import sys; sys.path.insert(0, 'tests'); import test_scanner as m; print(m.test_every_rule_fires(), m.test_safe_sql_not_flagged())"</pre><p>It prints <code>None None</code> when everything passes, and raises an AssertionError naming the failing rule or statement otherwise. The same check runs automatically on every push and pull request through GitHub Actions (see the Actions tab). The test file is written as plain functions, so pytest should also work, but that has not been tried.</p><h2>What has been verified</h2><ul><li>Checked by running it on a Windows machine: the CLI flags DROP TABLE, DELETE without WHERE and CREATE INDEX on the right lines, exits with 1 when something is flagged, and prints a usage message when no file is given.</li><li>All 10 rules fire on their example statements, and 13 safe statements (comments, strings, WHERE clauses, CONCURRENTLY, constraints, DO blocks) are not flagged. This passes locally on Windows and in GitHub Actions on Ubuntu with Python 3.12.</li><li>Not verified: pytest, macOS, and large real-world migration files.</li></ul><h2>Limitations</h2><ul><li>It is a regex scanner, not a full SQL parser. Treat it as a quick safety net, not a guarantee.</li><li>Code inside function bodies or DO blocks (dollar-quoted) is ignored, so risky statements there are not flagged.</li><li>Semicolons inside quoted identifiers can split a statement in the wrong place.</li><li>It only knows PostgreSQL-style syntax and a fixed set of rules.</li><li>Expect some false positives and false negatives.</li><li>The test suite is small: one example per rule plus 13 safe statements.</li></ul><h2>License</h2><p>MIT</p>
